# v0.3.0

## Image-reference change evidence

`v0.3.0` adds offline, literal image-reference transition findings for matched
containers in rendered Kubernetes workload manifests:

- `WORKLOAD_IMAGE_REFERENCE_CHANGED` (**medium**) when a matched container's
  non-empty image reference changes;
- `WORKLOAD_IMAGE_DIGEST_REMOVED` (**high**) when a previous `@sha256:`
  reference becomes one without a digest; and
- `WORKLOAD_IMAGE_LATEST_ADDED` (**high**) when a matched container changes to
  an explicit `:latest` tag, including tag-plus-digest forms such as
  `:latest@sha256:...`.

The comparison covers `containers`, `initContainers`, and
`ephemeralContainers`. Container identity includes its collection and name, so
same-name containers in different collections are compared independently.

## What these findings mean

The tool reports literal reference transitions in explicitly supplied rendered
manifests. A high finding preserves the CLI's existing exit status `1`.

## What these findings do not mean

This release does not contact a registry or Kubernetes cluster. It does not
resolve image references or establish image integrity, signature status,
provenance, SBOM contents, vulnerability status, runtime behavior, or safety.
An unchanged image reference is not an approval or assurance.

## Verification

The repository includes a sanitized acceptance fixture under
[`acceptance/v0.3.0/`](../acceptance/v0.3.0/) for the new image-reference
findings. The fixture is static test data only.
