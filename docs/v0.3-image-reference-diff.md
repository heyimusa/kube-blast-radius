# v0.3 image-reference change design

## Purpose

Make a changed container image reference visible in an offline Kubernetes
manifest security-impact diff. The feature reports a reference transition; it
does not resolve registries or establish image provenance, signature status,
or safety.

## Scope

Analyze named containers across `containers`, `initContainers`, and
`ephemeralContainers` for matched workloads. The identity is the workload
resource plus the container collection and name. Only a container present in
both before and after is compared. Adding/removing a container is outside this
feature.

| Code | Severity | Trigger |
|---|---|---|
| `WORKLOAD_IMAGE_REFERENCE_CHANGED` | Medium | A matched container's non-empty `image` string changes. |
| `WORKLOAD_IMAGE_DIGEST_REMOVED` | High | The old reference contains `@sha256:` and the new one does not. |
| `WORKLOAD_IMAGE_LATEST_ADDED` | High | The new reference explicitly uses `:latest` and the old one did not. |

A transition can emit the general medium finding and one or both high-signal
findings. Existing severity/exit behavior applies: any high finding exits 1.

## Explicit non-goals

- No registry, network, cluster, kubeconfig, credential, or image pull access.
- No parsing or normalization beyond literal `@sha256:` and final `:latest`
  recognition. The tool does not infer an implicit tag, registry host, platform,
  digest algorithm validity, or image equivalence.
- No signature, attestation, SBOM, CVE, or provenance verification.
- No security claim about an unchanged, digest-pinned, or any other image.

## TDD test plan

1. **RED:** a changed normal container image emits
   `WORKLOAD_IMAGE_REFERENCE_CHANGED` at medium severity; run the targeted test
   and confirm it fails because the code does not emit the finding.
2. **RED:** digest-to-tag transition emits `WORKLOAD_IMAGE_DIGEST_REMOVED` at
   high severity; confirm failure before implementation.
3. **RED:** a newly explicit `:latest` emits `WORKLOAD_IMAGE_LATEST_ADDED` at
   high severity; confirm failure before implementation.
4. **Regression:** unchanged image, newly added container, and removed
   container do not emit image-reference findings.
5. Cover init and ephemeral containers, then run `go test ./...`, `go vet ./...`,
   and a Docker build/test gate before review.

## Documentation requirements

Add the three codes to the README table and explicit limits. Wording must say
"reference" and "changed"; it must not say trusted, safe, signed, verified, or
provenance-checked.
